# Test VMs

Disposable KVM guests for tests that must never touch the live desktop: a real Hyprland, the session lock, PAM with faillock, greetd and D-Bus services. Each guest is a copy-on-write overlay on one base image. Take a slot, test, throw it away.

## Quick start

```sh
dev/vm/vm build-base                          # once, under a minute
slot=$(dev/vm/vm up --share "$PWD/target")    # about 4 s, prints the slot number
dev/vm/vm ssh "$slot" as-tester /work/debug/my-binary
dev/vm/vm screenshot "$slot" shot.png
dev/vm/vm down "$slot"
```

`up` prints only the slot number on stdout. Progress and the boot time go to stderr.

## Commands

| Command | Does |
|---|---|
| `build-base` | Rebuilds the base image with Docker. It runs `pacman -Syu` every time. |
| `up [--share DIR]` | Boots a fresh guest and prints its slot once Hyprland runs. `--share` mounts DIR read-only at `/work`. |
| `down SLOT` | Stops the guest and deletes its overlay. |
| `ssh SLOT [CMD...]` | Runs a command as root. The arguments are joined and run by the guest's shell, as with plain `ssh`. |
| `push SLOT SRC DST`, `pull SLOT SRC DST` | Copies files or directories with scp. |
| `screenshot SLOT OUT.png` | Runs grim in tester's session and copies the PNG back. |
| `key SLOT KEY...` | Presses keys through QMP. A key is a QEMU qcode, and `-` joins a chord: `ctrl-alt-t`, `super-q`, `ret`, `esc`. |
| `type SLOT TEXT` | Types text through QMP with a US layout. |
| `hid SLOT plug\|unplug` | Adds or removes the fake YubiKey. |
| `log SLOT` | Prints the serial console, the journal and the Hyprland log. |
| `list` | Lists running guests with their ports, owner and share. |
| `gc` | Stops guests whose owner process is gone and removes leftovers. |

`dev/vm/check.sh` runs the self-checks of the VM tooling against fresh guests and prints one line per check. It needs all slots free, because it starts 6 guests at once, and it refuses to run otherwise. It only ever stops guests it started. A run takes about 40 s.

## Running host binaries in the session

Build on the host and share the output directory. The guest's glibc is at least as new as the host's after `build-base`.

`as-tester CMD...` runs a command as `tester` with the session environment: `XDG_RUNTIME_DIR=/run/user/1000`, `WAYLAND_DISPLAY`, `HYPRLAND_INSTANCE_SIGNATURE`, `DBUS_SESSION_BUS_ADDRESS` and `NODEVICE_SELECT=1`.

```sh
# runs in the foreground and ends with the ssh command
dev/vm/vm ssh "$slot" as-tester /work/debug/my-binary --flag

# starts it as a child of Hyprland, like a keybind would
dev/vm/vm ssh "$slot" 'as-tester hyprctl dispatch "hl.dsp.exec_cmd(\"/work/debug/my-binary\")"'

# starts it detached from ssh with a log
dev/vm/vm ssh "$slot" 'as-tester setsid -f /work/debug/my-binary > /tmp/my-binary.log 2>&1 < /dev/null'
```

Files under `/work` keep their host owner and mode. Hyprland commands like `as-tester hyprctl dispatch ...` and `hyprctl eval` are fine here, because the guest is not the live session.

## The guest

- Arch Linux, booted with `-kernel` and `-initrd` and no bootloader. The root filesystem is the overlay on `/dev/vda`.
- `tester` (uid 1000, password `tester`) is logged in automatically by greetd into Hyprland. The output is `Virtual-1` on vkms at 1280x720, rendered by llvmpipe. Vulkan clients get lavapipe.
- Root logs in over SSH with a key generated by `build-base`. Password login is off.
- dbus-broker runs the system bus and tester's session bus. foot, grim and wtype are installed.
- `restart-session` ends tester's session and logs in again. Use it after changing `/home/tester/.config/hypr/hyprland.lua` or after a crash. greetd runs its autologin only once per boot unless its runfile is gone, and the script removes it.
- `wait-hyprland [SECONDS]` waits until Hyprland reports a monitor.
- The journal lives in memory. Hyprland logs to `/run/user/1000/hypr/<signature>/hyprland.log`.

### PAM and the fake key

The `deskshell-test` service has the shape of the host's `system-auth`, with `pam_fakeu2f.so` in place of `pam_u2f.so`:

```
auth  required                 pam_faillock.so  preauth
auth  [success=1 default=bad]  pam_fakeu2f.so   cue
auth  [default=die]            pam_faillock.so  authfail
auth  optional                 pam_permit.so
auth  required                 pam_env.so
auth  required                 pam_faillock.so  authsucc
```

- The key counts as present while a hidraw device with USB vendor 1050 exists. `vm hid SLOT plug` starts `fake-yubikey.service`, which creates a uhid device `1050:0407` named like a YubiKey. `unplug` stops it.
- Without a key the module fails at once and prompts for nothing, like pam_u2f. The stack still counts it as a failure.
- With a key it asks `Please enter the PIN: ` (echo off), sends `Please touch the FIDO authenticator.` as info, and succeeds when the PIN matches. These are pam_u2f's strings.
- `/etc/fakeu2f.conf` holds `pin=123456` and `touch_delay_ms=0`. A delay makes the module wait for the "touch" outside any conversation callback, as pam_u2f does. That is the window for SIGKILL tests.
- faillock uses its defaults: 3 failures lock the account for 600 s. Preauth is `required`, so a locked account still gets the PIN prompt, then fails. pam_faillock also delays every failed attempt by about 2 s, an absent key included, as on the host. `/run/faillock/tester` is created at boot and owned by tester, so PAM runs as tester can update it. Reset with `faillock --user tester --reset`.
- `pam-try [-s SERVICE] [-u USER] [ANSWER...]` runs `pam_authenticate`, prints each message as `prompt:`, `info:` or `error:`, answers prompts in order and prints `result:`. Run it as tester with `as-tester pam-try 123456`.

### Output hotplug

The guest kernel's vkms supports configfs. A device made under `/sys/kernel/config/vkms` gets connectors whose `status` file plugs (`1`) and unplugs (`2`) them, and Hyprland adds and removes the monitor. aquamarine does not pick up new DRM devices at runtime, so create the device first and then run `restart-session`. `check.sh` has a minimal device as an example.

### Quirks

- `vgem` is loaded so the system has exactly one render node. vkms has none. Without a render node, aquamarine fails to create its renderer and retries on every commit, with five error lines per frame in the Hyprland log. With vgem, aquamarine falls back to the sole render node, and Hyprland renders with llvmpipe through Mesa's EGL device for vgem. Scanout stays on vkms.
- `NODEVICE_SELECT=1` is set for the session and by `as-tester`. Mesa's Vulkan device-select layer crashes in `vkEnumeratePhysicalDevices` in this guest, with or without vgem.
- QEMU has no PS/2 controller, so the keyboards are `qemu-virtio-keyboard` and the ACPI power button. Pointer tests can use `qemu-virtio-tablet` through QMP `input-send-event`.
- File capabilities set by packages (for example on `newuidmap`) are missing in the image.

## Slots and resources

- Slots 1 to 6. Slot k uses SSH on `127.0.0.1:22200+k` and VNC on `127.0.0.1:5900+k`. VNC is wayvnc inside the session, without a password, reachable only from localhost.
- The slot directory holds the overlay, the QMP socket `qmp`, `serial.log`, `qemu.pid` and the owner.
- QEMU holds the slot's `flock` on `lock` for its whole life, so a crashed guest frees its slot. `up` waits for a free slot. A second lock on `ctl` keeps `up`, `down` and `gc` from changing one slot's files at the same time.
- Each guest runs in a `systemd-run --user` scope with a low CPU weight, pinned to the CPUs without V-Cache. It gets 2 vCPUs and 3 GiB.
- Networking is QEMU user mode with forwards bound to 127.0.0.1. No bridges, no root and no libvirt.
- Guests reach the internet through QEMU's user-mode NAT. A shell in full mode fetches DuckDuckGo's bang list and the holiday feed at start. When a check must stay offline, remove the guest's default route and turn off IPv6 on its interface first (`ip route del default`, `sysctl -w net.ipv6.conf.enp0s1.disable_ipv6=1`).
- The base image is about 1.5 GB. An overlay starts at a few MB.

### Owners and gc

`up` records an owner process. By default it is the nearest ancestor of `vm` that is not a shell or a wrapper like `timeout`, so a guest survives the single shell an agent's tool call runs in. Set `DESKSHELL_VM_OWNER=<pid>` to tie a guest to a specific process, for example a test runner. `gc` and every `up` stop guests whose owner has exited. Owners are tracked by pid and start time, never by matching command lines.

Tests should still call `down` themselves, for example from a trap:

```sh
slot=$(dev/vm/vm up)
trap 'dev/vm/vm down "$slot"' EXIT
```

## Environment

| Variable | Default | Meaning |
|---|---|---|
| `DESKSHELL_VM_DIR` | `${XDG_DATA_HOME:-$HOME/.local/share}/deskshell-vm` | images, key and slot directories |
| `DESKSHELL_VM_SLOTS` | 6 | number of slots, at most 6 |
| `DESKSHELL_VM_CPUS` | 2 | vCPUs per guest |
| `DESKSHELL_VM_MEM` | 3G | memory per guest |
| `DESKSHELL_VM_HOST_CPUS` | 8-15,24-31 | host CPUs the guests may use |
| `DESKSHELL_VM_CPU_WEIGHT` | 20 | CPU weight of each guest's scope (the default for other units is 100) |
| `DESKSHELL_VM_WAIT` | 600 | seconds `up` waits for a free slot |
| `DESKSHELL_VM_BOOT_TIMEOUT` | 120 | seconds `up` waits for Hyprland |
| `DESKSHELL_VM_OWNER` | see above | owner pid |

## How the base image is built

1. `image/Dockerfile` starts from an Arch image pinned by digest and runs `pacman -Syu` with the guest packages. A stamp argument makes this layer rerun on every build. Packages come from a BuildKit cache mount, so only new ones are downloaded.
2. A helper stage compiles `pam-fakeu2f/` and `fakehid/` with gcc.
3. `image/rootfs/` and `image/tester/` are copied in. Users, services, host keys and the root `authorized_keys` are set up.
4. BuildKit writes the final filesystem as a tar stream, and `mkfs.ext4 -d -` turns it into an ext4 image without root.
5. `debugfs` extracts the kernel and initramfs, and `qemu-img` converts the image to `base.qcow2`, which is read-only from then on.

Docker keeps the build cache, including the package cache mount `deskshell-vm-pacman`. `docker buildx du` shows it. `docker builder prune` drops all of Docker's build cache, not only this one. Deleting `DESKSHELL_VM_DIR` removes the images, the key and the slots.

## Probes

`crates/hypr/examples/vm_probe.rs` drives the guest's Hyprland and checks the hypr client and store against it. It refuses to run outside a guest. The build and run commands are at the top of the file.
